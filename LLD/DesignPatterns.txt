What is Design Pattern ?
A design pattern is a general, reusable solution to a commonly occurring software design problem. 
It provides a proven approach for organizing classes and objects to make software more maintainable, flexible, and extensible.


Important: A design pattern is not a piece of code that you copy and paste. It is a design approach that you adapt to your 
           particular problem.



Why do we need Design Patterns ?

Imagine you are developing a payment application. Initially, your application supports only Credit Card payments.
Now, your requirements change. You need to support UPI, Net Banking and Wallet payments.
This works, but as more payment methods are added, the method keeps growing and requires modification whenever a new payment type is 
introduced.
The problem isn't simply that the code contains if-else statements. The deeper issue is that payment processing for different methods is
tightly grouped inside one class.



How can design patterns help ?
A suitable design pattern, such as the Strategy Pattern, can separate each payment method into its own implementation 
and allow the application to select the required payment behavior.


Three categories of design patterns in java:

In Design Patterns, the 23 classic Gang of Four (GoF) patterns are classified into three categories: Creational, Structural, and Behavioral.


1. Creational Design Patterns :
  Creational design patterns are design patterns that deal with the process of object creation. They provide different ways to
  create objects while reducing unnecessary dependencies between the code that creates an object and the concrete class of that object.

  Five Creational Patterns :

  Pattern	             Main purpose
  Singleton	               Restricts a class to one shared instance
  Factory Method	       Lets subclasses or factory implementations determine which concrete object to create
  Abstract Factory	       Creates families of related objects
  Builder	               Constructs a complex object step by step
  Prototype	               Creates objects by copying an existing prototype

Remember: Creational patterns answer the question, "How should objects be created?"


2. Structural Design Patterns :
  Structural design patterns describe how classes and objects can be combined to form larger structures
  while keeping the resulting design flexible, reusable and easier to maintain.

Why do we need Structural Patterns?
  Imagine you are developing a movie investment platform. You have separate components for authentication, payments, movie projects and investor portfolios.
  As your application grows, you need to organize these components so they work together without creating unnecessary dependencies.
  Structural patterns help you design relationships and wrappers between objects to achieve this.

  Seven Strucutural Patterns :

  Pattern	    Main purpose
   Adapter	     Makes incompatible interfaces work together
   Bridge	     Separates an abstraction from its implementation
   Composite	 Treats individual objects and groups of objects uniformly
   Decorator	 Adds responsibilities to an object dynamically
   Facade	     Provides a simplified interface to a complex subsystem
   Flyweight	 Shares common state to reduce memory usage
   Proxy	     Controls access to another object

 Remember: Structural patterns answer the question, "How should classes and objects be organized or connected?"


3. Behavioral Design Patterns :
  Behavioral design patterns deal with communication and interaction between objects. They help distribute responsibilities 
  and define how objects collaborate to perform a task.


  Why do we need Behavioral Patterns?
   Imagine your movie investment platform supports several payment methods.
   Each payment method has different processing logic. You want to select the appropriate behavior without filling one large 
   method with multiple if-else conditions.
   The Strategy Pattern allows you to encapsulate each payment algorithm separately and select the appropriate one when needed.
   Behavioral patterns help make interactions between objects more organized and flexible.


  Eleven Behavioral Patterns :

  Pattern	               Main purpose
   Strategy	                 Select between interchangeable algorithms
   Observer	                 Notify interested objects when an event occurs
   State	                 Change behavior according to an object's current state
   Command                   Represent a request as an object
   Chain of Responsibility	 Pass a request through a chain of handlers
   Template Method	         Define an algorithm's structure while allowing certain steps to vary
   Iterator	                 Traverse a collection without exposing its internal representation
   Mediator	                 Coordinate interactions between multiple objects
   Memento	                 Capture and restore an object's previous state
   Visitor	                 Add operations to object structures without placing those operations in the element classes
   Interpreter	             Define and evaluate a simple language or grammar


Remember: Behavioral patterns answer the question, "How should objects communicate and share responsibilities?"







The most important patterns are :

Category	    Patterns
Creational	     Singleton, Factory Method, Builder
Structural	     Adapter, Decorator
Behavioral	     Strategy, Observer, State



I. Creational Design Patterns:



1. Factory Method Pattern
  Interview definition:
  The Factory Method Pattern is a creational design pattern that defines an interface or abstract method for creating an object
  and allows subclasses to decide which concrete class to instantiate.

  In simple words: It delegates the decision of which concrete object to create to subclasses.
  Example: A notification system uses different creators to create EmailNotification or SmsNotification objects through the same 
           factory method.


2. Abstract Factory Pattern
  Interview definition:
  The Abstract Factory Pattern is a creational design pattern that provides an interface for creating families of related 
  or dependent objects without specifying their concrete classes.

  In simple words: It provides a common factory interface for creating a group of related objects that are designed to work together.
  Example: A notification system uses an EmailFactory to create an EmailSender and an EmailFormatter, or an SmsFactory to create 
           an SmsSender and an SmsFormatter.



3. Builder Pattern
  Builder Pattern is a Design patern that helps us to create complext objects easily, by keeping the object creation process flexible,
  readible, and maintainable.

  A Builder is a class or component responsible for collecting the values required to construct an object and creating the final 
  object when requested.
  

  Fluent Interface:
  A Fluent Interface is an API design technique that allows method calls to be chained together in a readable and expressive way. 
  In Java, it is commonly implemented by returning the current object from methods. The Builder Design Pattern often uses a Fluent Interface
  to configure an object through chained method calls.
